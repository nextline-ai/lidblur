# 측정 결과 정리

원본(Apple iPhone Duo 페이지 '폴더블 디자인' 슬라이더)은 **시각 비교용으로만** 사용했습니다.
Apple의 코드·셰이더·장면 파일·텍스처는 열람하거나 저장소에 포함하지 않았고, 캡처한 비교용 프레임도 저장소 밖에만 두었습니다.

## 덮개 각도 센서 (Mac16,8, macOS 27.2)

- HID 기기 `las`: VID `0x05AC`, PID `0x8104`, usage page `0x20`, usage `0x8A`, Transport `SPU`.
- Feature report ID 1, 길이 3: `[01, lo, hi]` → 정수 각도(도). 읽기 1회 약 0.6 ms.
- 해상도가 1°라서 앱에서는 프레임 단위 lerp로 부드럽게 만듭니다.
- 프로토타입: `Prototypes/LidProbe/main.swift` (`swiftc -O main.swift -o lidprobe && ./lidprobe 10`).

## 원본 효과의 실제 모양 (측정)

방법: Chrome에서 WebGL 캔버스 프레임을 진행도 0.05 간격으로 캡처 → 카메라를 향해 기울어지는 패널을
호모그래피로 평평하게 편 뒤, 완전히 펼친 프레임과 띠(band)별로 비교해 블러 σ와 밝기 비율을 맞췄습니다.
(배경화면이 접힘에 따라 확대되므로 블록별 정렬을 따로 했습니다.)

- 블러와 음영은 **기울어지는 패널의 바깥쪽 끝(경첩의 반대편)으로 갈수록** 강해집니다.
  맥북에서는 화면 **위쪽**에 해당합니다. (설정에서 경첩 쪽으로 바꿀 수 있음)
- 블러 LOD는 경첩→끝 방향으로 거의 선형으로 증가하고, 경첩 근처에도 이미 일부(최대치의 약 45%)가 있습니다.
- 블러는 접기 시작 직후 빠르게 붙고(진행도 0.9에서 이미 최대치의 약 70%) 0.75~0.8 근처에서 포화합니다.
- 음영 = 전체 어두워짐(≈ c^1.5, c = 1 − 진행도) × 끝쪽 어두워짐(c≈0.3에서 포화) × 긴 변 가장자리의 좁은 어두운 띠.

| 진행도 v | 경첩 근처 밝기 | 끝 근처 밝기 |
|---|---|---|
| 0.9 | 0.97 | 0.80 |
| 0.8 | 0.91 | 0.49 |
| 0.7 | 0.83 | 0.25 |
| 0.6 | 0.71 | 0.24 |

현재 기본값으로 같은 측정을 내 렌더러에 돌렸을 때 원본과의 평균 차이:
블러 |Δlog2σ| ≈ 0.33 옥타브(측정 격자 간격 수준), 밝기 |Δ| ≈ 0.018.

## 맥북으로 옮길 때의 대응

- 원본 진행도 v ↔ 앱 진행도 p (1 = 열림, 0 = 닫힘). 덮개 각도 → p 매핑은 `openAngle`/`closedAngle`/`angleCurve`로 조정.
- 블러 크기는 패널 크기에 비례하도록 `log2(화면 높이 / 1335)`만큼 LOD를 보정(`scaleToPanel`).
